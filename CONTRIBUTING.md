# Contributing to QuanSweep

Thank you for helping make QuanSweep better. This project is maintained by Quanvio Lab as an open-source Mac utility, and community contributions are welcome.

## How to contribute

1. **Open an issue first** for bugs or feature requests so we can agree on direction before you spend time on code.
2. **Fork the repository**, create a branch, and make your changes.
3. **Keep changes focused** — a small, well-tested pull request is much easier to review than a large rewrite.
4. **Build and run locally** before submitting:

   ```bash
   make run      # quick run from source
   make app      # build QuanSweep.app
   make zip      # build the release zip
   ```

5. **Update documentation** if your change affects behavior, installation, or the UI.
6. **Open a pull request** with a clear description of the problem and the fix.

## Coding style

- Follow the existing Swift style in `Sources/QuanSweep/`.
- Prefer public macOS APIs (`Foundation`, `AppKit`) over third-party dependencies.
- Keep the app safe: every cleanup action must go through the confidence engine and quarantine system.
- Add comments only when the code is not self-explanatory.

## What we are looking for

- Bug fixes, especially for false positives in app-residue detection.
- New scanner modules that follow the existing safety model.
- UI/UX polish that keeps the interface clean and professional.
- Documentation improvements.

## What we are not looking for

- Heavy rewrites or new dependencies that conflict with the lightweight goal.
- Changes that bypass the quarantine or protection systems.
- Content generated by automated coding assistants included directly in issues, pull requests, or committed code.

## Reporting bugs

When reporting a bug, please include:

- macOS version and Mac model (Apple Silicon or Intel).
- Steps to reproduce the issue.
- Expected vs actual behavior.
- Whether Full Disk Access was granted.
